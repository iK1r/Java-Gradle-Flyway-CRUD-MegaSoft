# MegaSoft — Flyway і CRUD, модуль 8

У восьмому домашньому завданні я продовжив роботу з проєктом MegaSoft із сьомого модуля. Замість ручного запуску SQL-файлів для створення та наповнення бази використав **Flyway**. Також написав `ClientService`, через який можна додавати, знаходити, перейменовувати й видаляти клієнтів.

## Міграції Flyway

Міграції лежать у `src/main/resources/db/migration`:

- `V1__init_db.sql` — створює таблиці `worker`, `client`, `project` та `project_worker` зі зв'язками й обмеженнями.
- `V2__populate_db.sql` — додає дані з попереднього завдання. У кінці міграції я також налаштував наступні значення ID: раніше записи додавалися з конкретними ID, тому без цього новий клієнт міг би отримати зайнятий ID.

Тепер замість `DatabaseInitService` та `DatabasePopulateService` використовую `DatabaseMigrationService`. Він викликає `Flyway.migrate()`, а після виконання показує кількість нових міграцій і стан кожної застосованої міграції. Flyway веде історію в таблиці `flyway_schema_history`, тому міграції не повторюються при наступних запусках. Старий код для читання й виконання `init_db.sql` та `populate_db.sql` прибрано.

## ClientService

Клас `Client` має два поля — `id` і `name`. У `ClientService` реалізовано всі методи із завдання:

| Метод | Для чого потрібен |
| --- | --- |
| `long create(String name)` | Створити клієнта й отримати новий ID |
| `String getById(long id)` | Знайти ім'я клієнта за ID (або `null`, якщо його немає) |
| `void setName(long id, String name)` | Змінити ім'я |
| `void deleteById(long id)` | Видалити клієнта |
| `List<Client> listAll()` | Отримати всіх клієнтів |

Для запитів використовую `PreparedStatement`. Параметри передаю окремо через `setString()` і `setLong()`. У `create()` отримую новий ID через `getGeneratedKeys()`.

Є перевірки вхідних даних: ID повинен бути додатним, а ім'я після видалення зайвих пробілів — мати від 2 до 1000 символів. Якщо дані неправильні, метод викидає `IllegalArgumentException`. Також `setName()` та `deleteById()` повідомляють про неіснуючий ID.

## Як запустити

Відкрити папку проєкту в IntelliJ IDEA і дочекатися, поки Gradle завантажить залежності `h2` та `flyway-core`. Потрібна встановлена Java. Якщо у вас немає Gradle Wrapper, його можна перенести з попереднього Gradle-проєкту.

У PowerShell із кореня проєкту:

```powershell
.\gradlew.bat migrateDb
.\gradlew.bat queryDb
.\gradlew.bat clientDemo
```

Після першого запуску `migrateDb` у логах мають бути обидві успішні міграції:

```text
Flyway migrations executed now: 2
V1__init_db.sql - Success
V2__populate_db.sql - Success
```

При другому запуску кількість **нових** міграцій буде `0` — це нормально: Flyway пам'ятає виконані версії.

`queryDb` запускає запити із сьомого модуля. `clientDemo` створює тимчасового клієнта, перевіряє читання, зміну імені, список клієнтів, видалення та валідацію. Тимчасового клієнта наприкінці видаляє, тому початкові п'ять клієнтів залишаються.

База H2 створюється в `data/megasoft.mv.db`. Папка `data/`, службові файли IntelliJ й кеш Gradle виключені через `.gitignore`. Якщо потрібно перевірити саме **перший** запуск міграцій, можна закрити програму й видалити локальну папку `data` (усі локальні дані буде втрачено), а тоді знову виконати `migrateDb`.
